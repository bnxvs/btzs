# Plotter for macOS

Кроссплатформенный порт приложения **Plotter for Windows v1.2** (BTZS Software /
The View Camera Store, автор Phil Davis) — программы построения графиков и
сенситометрического анализа чёрно-белых фотоматериалов по зонной системе BTZS.

Порт воспроизводит функциональность оригинала (кривые плёнки и бумаги, анализ
EFS/G-bar/SBR, зоны сюжета, сопоставление плёнка↔бумага, ступенчатые клины, графики,
печать) и полностью совместим с его форматами файлов.

Интерфейс — современный: одно окно с вкладками документов и иконочная панель
команд. Внешний вид MFC-приложения 2003 года (MDI-окна каскадом/мозаикой,
строковое меню, индикаторы режимов клавиатуры) намеренно не воспроизводится —
сохранён паритет функциональности и данных, а не «пиксель в пиксель».

## Стек

- **React 18 + TypeScript** (сборка — Vite).
- **Tauri v2** — упаковка в нативное приложение macOS (`.app`/`.dmg`).
- **Vitest + Testing Library** (jsdom) — тесты.
- Тексты интерфейса — из каталогов переводов (`ru`, `en`), без жёстко заданных
  подписей.

## Структура

```
src/
  core/
    model/      типы домена, константы, фабрики документов, операции над кривыми
    format/     кодеки .pfc/.ppc/.pmf, CP1251, legacy-импорт
    analysis/   чистое расчётное ядро (EFS, G-bar, SBR, зоны, ISO Range, сопоставление)
  store/        состояние приложения: документы/оболочка, опции, печать, клины
  ui/           окна, вкладки, команды, диалоги, графики, печать
  i18n/         каталоги переводов и региональное форматирование
src-tauri/      оболочка Tauri v2 (окно, диалоги, файловая система)
app/            образцы данных и справка оригинала (реверс-инжиниринг)
docs/           документация по форматам (btzs-format.md)
openspec/       спецификация изменений (change `macos-port`)
```

Слои зависят строго в одну сторону: `ui` → `store` → `core/*` и `i18n`.
`core/model` не зависит от `core/format`, `core/format` не зависит от
`core/analysis`.

## Развёртывание на сервере (Docker)

Приложение — статическая SPA без серверной части, поэтому на VPS оно
раздаётся как статика через nginx. В браузерном режиме работа с файлами идёт
через `<input type="file">` и скачивание (`src/ui/file-service.ts` сам выбирает
бэкенд), так что дополнительных сервисов не требуется.

Быстрый запуск на VPS:

```sh
cp .env.example .env      # при необходимости поправьте порт/привязку
./scripts/deploy.sh
```

Либо напрямую:

```sh
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/healthz   # → ok
```

По умолчанию контейнер публикуется на `127.0.0.1:8080` — это подходит, если
перед ним уже стоит обратный прокси. Для прямого доступа извне задайте в
`.env`:

```
PLOTTER_BIND=0.0.0.0
PLOTTER_PORT=80
```

### Прокси и HTTPS (Nginx Proxy Manager)

TLS и обратный прокси выполняет внешний **Nginx Proxy Manager** (NPM) — этот
проект его не поднимает. Контейнер публикует порт на хост (по умолчанию
`127.0.0.1:8080`), и NPM проксирует на него. В NPM создайте Proxy Host:

- **Domain Names** — ваш домен;
- **Scheme** — `http`;
- **Forward Hostname** — `127.0.0.1`;
- **Forward Port** — `8080` (значение `PLOTTER_PORT` из `.env`);
- **Block Common Exploits** — включить; **SSL** — запросить Let's Encrypt.

Это работает независимо от режима сети NPM, в том числе при
`network_mode: host` (как в типовой установке NPM на VPS): при host-сети у
NPM нет docker-DNS, поэтому адрес задаётся как `127.0.0.1:<порт>`, а не по
имени контейнера. Занятость порта проверяется так:

```sh
ss -ltn | grep :8080
```

## Совместимость форматов

Приложение читает и записывает **оба** направления без потерь:

- `.pfc` — документ плёнки (`BTZSFILM`);
- `.ppc` — документ бумаги (`BTZSPAPR`);
- `.pmf` — документ сопоставления / эталонной кривой (`BTZSPAP`).

Неизвестные и нереверсенные поля сохраняются «как есть» (сырые заголовки,
`reserved`-байты), поэтому запись файла, прочитанного из Windows-версии, даёт
побайтово идентичный результат. Строки кодируются в CP1251.

### Как проверить совместимость

Круговая совместимость проверяется автоматическими тестами на полном наборе
образцов из `app/` (`src/core/format/plotter-file.test.ts` и
`src/ui/shell/integration.test.tsx`, группа 13):

```sh
npm test -- src/core/format/plotter-file.test.ts
npm test -- src/ui/shell/integration.test.tsx
```

Каждый образец `.pfc`/`.ppc` проходит цикл «байты → документ → байты» и
сверяется с исходными байтами; документы сравниваются до и после повторного
открытия.

### Ручная проверка на файлах Windows-версии

1. Откройте файл кнопкой **Open** (Ctrl+O) или создайте документ
   (**New Film** Ctrl+F / **New Paper** Ctrl+N / **New Matcher** Ctrl+M).
2. Убедитесь, что все вкладки (Family/Data/Analyze/Charts для плёнки и бумаги;
   Info/Film/Paper/Compare для сопоставления) отображаются корректно.
3. Сохраните файл (**Save** Ctrl+S) и сравните его с исходным — размер и
   содержимое должны совпадать.

## Локализация

Интерфейс полностью переведён на русский язык; язык по умолчанию — системный,
при отсутствии каталога используется русский. Выбор языка запоминается между
запусками. Числа форматируются с десятичной запятой, даты — в формате
`ДД.ММ.ГГГГ`. Все подписи берутся из каталогов переводов (`src/i18n/`).
